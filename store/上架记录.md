## 实测可用的提交流程（Partner Center）

全部经自动化实测（页面：`/packages`、`/listings`、`/submission`）：

1. **换程序包**：`Input.dispatchDragEvent`（dragEnter → dragOver → drop，`data.files` 给 zip 绝对路径）投到「将程序包拖到此处」区域；约 6 秒后行变成新版本 + `已完成`。合成 File / 隐藏 input 的 `setFileInputFiles` 都不可靠。
2. **截图/磁贴上传（关键）**：必须把「点 `#add_screenshot_button`」和「注入文件」放在**同一次 JS 执行**里，否则上传器不认：
   ```js
   const btn = document.getElementById('add_screenshot_button'); btn.click();
   const f = new File([Uint8Array.from(atob(window.__up), c=>c.charCodeAt(0))], 'screenshot-3.png', {type:'image/png'});
   const inp = document.querySelectorAll('input[name=fileuploader]')[1];   // [0]=徽标, [1]=截图
   const dt = new DataTransfer(); dt.items.add(f); inp.files = dt.files;
   inp.dispatchEvent(new Event('input',{bubbles:true}));
   inp.dispatchEvent(new Event('change',{bubbles:true}));
   ```
   base64 要**分块注入**（每次 ≤40 KB，单次 100 KB 会报 `chunk is longer than limit`），上传完成约 9–15 秒后缩略图出现。
3. **删除截图**：点 `button[aria-label="删除屏幕截图 screenshot-N.png"]` → 弹 CDK 确认框 → 点其中的 `v6_he-button`（文本 确认）。注意：**每次点击都会叠加一个确认框**，堆叠后先全部取消再单步操作。列表清空后可重新上传（顺序＝上传顺序，所以直接全删再按 1→2→3→4 重传可顺便修正顺序）。
4. **⚠️ 徽标别误伤**：`upload_file(".app-task-menu input[type=file]")` 会命中**第一个**匹配（徽标），把截图塞进徽标会导致保存报「文件大小不正确（需 1:1）」。清掉的办法＝重载编辑器（丢弃未保存的待传文件），已保存的徽标不受影响。
5. **每次提交都要重填「认证说明」**（不会继承上次），选 `#testerInfoNo`（不需要测试凭据），`#publishButton` 由灰变可点后再点发布；页面先显示「正在发布」，随后 `/packages/dashboard` 上会短暂显示`正在草拟`，**几分钟后**才变`正在审阅`——别在`正在草拟`阶段重复点发布。
6. 语言：`为所有语言复制此徽标` / `复制所有语言的促销磁贴` 可用；**`为所有语言复制这些屏幕截图磁贴` 实测点了没把英文的新截图刷到中文一览**（中文一览的截图与顺序是独立数据，未验证成功）。

## v1.0.5 提交实录（2026-09-27 凌晨）· 上传通道与发布的坑

**结论：包已上传、提交已进入「正在审阅」（预计 7 个工作日）。换包后 Store 一览没有被清空**（五个必需步骤全绿，省掉了重填一览）。

### 换包上传：可靠通道 = base64 注入 + 合成 drop 事件
- `opencli upload` 对隐藏 `input[type=file]` 照旧失败（`fileChooserOpened not received`）。
- **页面里 `fetch('http://127.0.0.1:…')` 会永久挂住**（本地服务返回 200 + CORS 头都对，也照样挂；前台/后台窗口都一样）——所以「本地 CORS 服务 + 页面 fetch」这条路在本机走不通，别在这上面耗。
- **可行做法**：把 zip 转 base64 → 分片 `window.__b64 += '<片段>'` 注入（9000 字符/片，共 8 片）→ 页面里 `atob` 还原成 `Uint8Array` → `new File` → `new DataTransfer()` + `items.add` → **对拖放区派发 dragenter/dragover/drop**。实测成功（`files=1 size=53395`），随后页面显示「正在上传」，**几分钟后 packages 表出现 1.0.5 / 已完成**。
- ⚠️ **「正在上传」不代表卡死**：它可能只是界面没刷新，实际已经传完。别急着重试或重载——重载会让上传跑到一半（本次重载时 CDP 直接 `cdp_timeout`）。**先等 2–3 分钟再查 packages 表。**

### 调用 opencli 的两个坑（本次踩到）
- **别用 `opencli.cmd`**：它经 `cmd.exe`，长参数（base64）会被处理坏，表现为 eval **静默返回空**（`window.__b64` 长度始终 0）。改成直调 `node <opencli>/dist/src/main.js …`，参数直达，一次成功。
- **Python 里调 opencli 的写法**：`subprocess.run([node, ENTRY, "browser", "pc", "eval", js])`，`OPENCLI_WINDOW=foreground`；单次 eval 载荷 ≤ ~9000 字符最稳。

### 发布按钮解禁
- 解禁条件 = **认证说明已填 + `#testerInfoNo` 已选**（本次实测：JS `.click()` 设单选**也够**，不必真实鼠标点击；配方里「必须 click_at_xy」这条对本页面不成立）。
- **表单不持久**：`/submission` 一重载，说明与单选全部清空（`0/2000`、`testerInfoYes` 回勾）。必须**打开页面 → 填 → 点发布**一口气做完。
- 点发布后仪表盘先显示 **`正在草拟`**；本次约 **20 分钟**才转 **`正在审阅`**（配方原先写「几分钟」，实测更久——**别在草拟阶段重复点发布**）。

### 查页面状态的经验
- Partner Center SPA 常只渲染出导航条，`innerText` 只有几百字符；**不要靠正文渲染判断**，改用 `document.body.innerText.indexOf('正在审阅')>=0` 这类**关键词布尔查询**，最可靠。
- 页面上有隐藏的「需要登录」弹窗模板（`vis:false`、0×0），**它不是会话过期的证据**，别被它误导。
